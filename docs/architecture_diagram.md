# Архитектурная диаграмма системы автоматического обновления базы знаний

## Диаграмма в формате Mermaid

```mermaid
graph TD
    A[Источник данных<br/>knowledge_base/] --> B[Скрипт обновления<br/>update_index.py]
    B --> C{Сканирование изменений}
    C --> D[Новые файлы]
    C --> E[Изменённые файлы]
    C --> F[Удалённые файлы]
    
    D --> G[Загрузка документов]
    E --> G
    G --> H[Разделение на чанки<br/>RecursiveCharacterTextSplitter]
    H --> I[Генерация эмбеддингов<br/>all-MiniLM-L6-v2]
    
    I --> J{Индекс существует?}
    J -->|Да| K[Загрузка существующего индекса FAISS]
    J -->|Нет| L[Создание нового индекса FAISS]
    
    K --> M[Объединение эмбеддингов]
    L --> M
    
    M --> N[Сохранение индекса<br/>faiss.index]
    M --> O[Сохранение метаданных<br/>index_metadata.pkl]
    M --> P[Сохранение чанков<br/>index_chunks.pkl]
    
    F --> Q[Удаление чанков<br/>из индекса]
    Q --> M
    
    B --> R[Логирование]
    R --> S[Файл логов<br/>update_log.jsonl]
    R --> T[Консольный вывод]
    
    U[Планировщик cron] --> B
    U --> V[Ежедневный запуск<br/>в 06:00]
    
    W[Состояние системы] --> B
    B --> W
    W --> X[Файл состояния<br/>index_state.json]
    
    N --> Y[Векторная БД FAISS]
    O --> Y
    P --> Y
    
    Y --> Z[RAG-бот<br/>telegram_bot.py]
```

## Ключевые компоненты

1. **Источник данных**: `knowledge_base/` (документы .md/.txt)
2. **Скрипт обновления**: `update_index.py` (сканирование, обработка, обновление)
3. **Процесс обработки**: чанки → эмбеддинги → FAISS индекс
4. **Логирование**: `update_log.jsonl` + консольный вывод
5. **Планировщик**: cron/Task Scheduler (ежедневно в 06:00)
6. **Состояние системы**: `index_state.json` (хеши файлов)

Диаграмма показывает полный поток данных от источника до обновлённого индекса, используемого RAG-ботом.
